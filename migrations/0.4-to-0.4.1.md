Mechanical migration for connector 0.4.0 → 0.4.1 (`sis search --all-sections`). **Non-breaking** — no file moves, no state migration, no re-login:

1. **Upgrade the connector** — reinstall `connectors/cuhksz-cli` at 0.4.1. Every existing `bb` / `sis` command, flag and output shape is unchanged.
2. **New flag (optional)** — `cuhksz-cli sis search --subject GFH --catalog 1000 --all-sections` expands every course's "View All Sections" list (SIS renders only the first 3 sections per course by default). It stays a read-only catalog query: the only actions sent are the existing search action and the page's `$ICFieldNNN$hviewall$0` expansion actions. Expansion is one AJAX request per expandable course, sequential and capped (default 30); a failed expansion degrades to the rendered sections for that course with a structured note instead of aborting.
3. **Output additions** — each course in `--format json` now carries `sections_complete` (and `sections_expanded`); the top level carries `all_sections` and, on a cap/failure, a `notes` list. Text output shows `N sections (all)` for expanded courses and groups `LEC:` / `TUT:` / `SUP:` sections when a course mixes types (a GE course's tutorial is what occupies the timetable).
4. **No action required** for existing installs — credentials, sessions, wiki pages and the sis/bb/registry territories are untouched; nothing needs manual editing.

If the user asks about the new behavior, relay the advisory line: 「本命令只提供课程信息的查询与参考建议；AI 不能保证给出最优选课方案，也不代替用户做决定；连接器是**只读**的——不选课、不加购物车、不交作业、不执行任何 state-changing 交易；最终以 SIS 与教务规定为准。」
