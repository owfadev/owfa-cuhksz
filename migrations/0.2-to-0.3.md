Mechanical migration for package 0.2 → 0.3 (connector-home substrate). Relay to the user in their language; the connector does the work, no manual file moves:

1. **Upgrade the connector first** — reinstall `connectors/cuhksz-cli` at 0.3.0 (the only console script is `cuhksz-cli`; `bb-cli` / `sis-cli` were removed, every command moves to `cuhksz-cli bb ...` / `cuhksz-cli sis ...` unchanged).
2. **Inspect the machine state** — `cuhksz-cli home status` (read-only: effective bb/sis paths, their source — substrate / explicit override / legacy fallback — and any legacy directories still present).
3. **Dry-run the migration** — `cuhksz-cli home migrate --dry-run` (moves nothing, registers no binding; reports `would-migrate` / `nothing-to-migrate` / `already-migrated` per component). The command pre-flights both components first: it refuses the whole run (structured JSON error) when `BB_CLI_HOME` / `SIS_CLI_HOME` is set for a component, or when a target component already holds files — nothing moves and no binding is written in that case.
4. **Migrate** — `cuhksz-cli home migrate` (one run moves both legacy directories: `~/.bb-cli` → `$OWFA_HOME/connectors/cuhksz-cli/homes/<id>/bb`, `~/.sis-cli` → `.../sis`; move, never copy; a symlink stays at each legacy path; the workspace binding is registered). No re-login is needed — credentials and sessions carry over.
5. **Verify** — `cuhksz-cli home status` shows both components under the substrate home, source `substrate`; `cuhksz-cli bb status` / `cuhksz-cli sis status` report the same session/credential evidence as before.

Never run the migration against a machine where the user has not confirmed: homes hold credentials and the move is not reversible except by hand. A legacy symlink left behind is a cleanup item for the human, never removed automatically.
